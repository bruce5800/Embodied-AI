# 实验日志 — SAC 抓取强化学习

按时间顺序记录所有训练 run 的"改动 / 结果 / 教训"。每次失败都揭示了一类 reward gaming 或工程坑。

## TL;DR

| 维度 | 起点 | 当前最佳 |
|------|------|----------|
| 算法 | SAC + 4-dim EE-space action | SAC + 6-dim joint-space action |
| 单训速度 | 单 env ~140 fps | 8 envs ~1300 fps（9× 加速）|
| best **placed** rate | 0% | **46%**（v10 yellow curriculum, 600k best_model） |
| best lift rate | 0% | **66%** |
| best mean_reward | -130 | +22（v9）|

最佳 ckpt：`checkpoints/m1_yellow_v10_600k/best_model.zip`
- 训练设置：`--obj-radius 0.05 --target yellow_cylinder --total-timesteps 600000 --n-envs 8`
- 物体仅在 zone_yellow ±5cm 内随机化（反向课程 stage 1）
- **重要**：用 `best_model.zip` 而非 `final.zip`，后者已退步（critic 漂移）

## 时间线

### v1 — 初始骨架（5k smoke + 500k baseline）

**配置**：4-dim EE-space action `[Δx, Δy, Δz, gripper]` + 单次 DLS IK + 26-dim obs

**v1 5k smoke**：pipeline 跑通，~900 fps

**v1 500k m1_red（单 env）**：
- success **0%** / lift_rate 20% / mean_reward -76
- 训练曲线：100k 处 reward 升到 -45 峰值，之后退步到 -85
- 现象：mean_length 250→184→222→158 一路缩短

**根因诊断**：**OOB 自杀逃跑 hack**——撞飞物体提前 truncate 逃 step_penalty + reach 负值。每步基础 reward -0.74，250 步 = -185；OOB 提前结束反而少受罚。

**修复**：reward 加 `oob_penalty -10`、reach clip 到 -1、first_lift +5 一次性 milestone。

---

### v2 → v3 — Action 空间从 EE-space 切到 joint-space

**v2** 在 EE-space 下经常 IK 不稳定（单次 DLS 多步累积漂移），决定切回 6-dim joint-space `[Δq1..5, gripper]`。

**同时引入**：
- `KP_BOOST = 3` —— 04 stage 的 actuator kp 太软（500），加大让 ctrl 跟踪到位
- 三组 collision groups —— 之前 arm 的 link5/gripper 撞地板下不去（contype/conaffinity 默认全 1）
- `_check_grip_contact()` 直接读 `mj_contact` 比 touch sensor 可靠

**结果**：infrastructure 变好，但 reward 还是有问题（继续 v3-v9 调）。

---

### v3 — 修 OOB hack + entropy 衰减

**改动**：
- 移除 touch_bonus（v1 里被刷分）、near_grip_bonus
- 加 `oob_penalty -10`、reach clip
- **固定 `ent_coef = 0.1`**（自动调节让 ent_coef 50k 内降到 0.0077，policy 过早 deterministic）

**v3 500k 结果**：success 0% / lift 20%
- mean_length 不再缩短（OOB hack 堵住）
- 但训练后期发散：reward 100-200k 升到 -42 峰值，500k 降到 -85

**教训**：
1. 自动 entropy 在 6-dim action 下 `target_entropy = -6` 太激进，固定 ent_coef 更稳
2. 500k 长训必崩，需 LR linear decay

**追加修复**：加 `lr_schedule` linear decay，base_lr × max(progress, 0.1)

---

### v4 — 突破：GRIPPER_CLOSE 加深 + first_lift_bonus 放大

**关键诊断**（用 diagnose.py 跑 50 ep）：
```
contacted 80%   ← agent 能碰到物体
lifted 3%       ← 但抓不住
final_obj_z 0.029m
```
**经典"碰但不抓"局部最优**——hover near object 拿满 reach reward，但不抓。

**改动**：
- `GRIPPER_CLOSE -30° → -45°`（XML range 下限是 -50°，给 RL 更深的"夹紧"动作空间）
- `R_FIRST_LIFT_BONUS 5 → 20`（强化"突破 hover plateau"激励）

**v4 200k 结果**：
- success **10%** / lift **40%** / mean_reward -27
- **第一次 success > 0%**！
- 200k step ≈ 3 min wall-clock

**教训**：reward 一次性 milestone（first_lift）比持续 dense reward 更能突破探索瓶颈。

---

### v5 — phase B 加猛了，崩

**动机**：v4 lifted 16% 但 placed 0%，运送阶段 reward 太弱。

**改动**：
- `W_TRANSPORT 1.0 → 3.0`（运送系数加大）
- `R_FIRST_NEAR_TARGET 0 → 15`（首次抓着靠近目标 +15 一次性）

**v5 500k 结果**：
- success 0% / lift 0% (final) / OOB **30%**！

**诊断**（best_model 50ep）：lift 30%（峰值 vs v4 的 16%）但 OOB 翻倍

**根因**：
- transport ×3 让 agent 抓起来后**急冲**目标区，物体被甩飞
- first_near +15 reward 跳跃太大让 critic 学崩，500k 后期发散

**教训**：phase B 信号要温和。reward 跳跃 > 5 容易让 critic 不稳。

---

### v6 — 回滚 + 新 hack：推杆刷分

**改动**：W_TRANSPORT 回 1.0，FIRST_NEAR 缩到 5

**v6 300k 结果**（10ep eval）：success 10% / lift 0% — **数学不可能事件**！

**诊断**（50ep）：
```
held (contact+close+lift) 0%
placed 14%
final_obj_z 0.025m
```
**新 reward gaming 浮出水面：agent 用 gripper 当推杆把物体在桌面滑到 zone**——placed 判定 `obj_z < 0.05 AND xy < 0.06` 没要求物体被抬起过。

---

### v7 — 堵推杆 hack：placed 必须 ever_lifted

**改动**：env 加 `_ever_lifted` flag（episode 内任一帧 obj_z > 6cm 就锁定 True），placed 判定加 `ever_lifted=True`。

**v7 300k 结果**：
- success 0% / lift 0% (final) / -89 mean_reward
- best_model 50ep：held 22%（真抓取！）/ placed **0%**

**新瓶颈**：agent 学会真抓取了，但**抓起来后不会运送到 zone**（phase B 还是不通）。

### 反向课程路线启动

**动机**：v4-v7 phase B 长链 SAC 学不到。改"先学短链"的反向课程：物体出生在 zone 旁边，运送距离 ≈ 0。

**实现**：`GraspEnv` 加 `curriculum_radius` 参数；`randomize_objects` 加 `target_override`。target 物体放在 zone center ±radius 方框内。

#### 课程 stage 1 (red zone, r=0.05) — 反而更差！

| 指标 | v7 全场景 (red) | stage 1 课程 red r=0.05 (300k) |
|------|---|---|
| approached | 38% | **28%** ↓ |
| lifted | 24% | **10%** ↓ |
| placed | 0% | 0% |

**反直觉发现**：zone_red (-0.15, -0.35) 在 SO-100 工作空间边缘 (Y=-0.35 接近极限)。全场景训练的"平均物体位置" (-0.30, 0.0) 恰好是工作空间中心，agent 学到了"中心倾向"。课程化把物体推到边缘反而更难。

**对策**：换中心 zone。

#### 课程 stage 1 (yellow zone, r=0.05) — 真突破

zone_yellow (-0.15, 0.0) 是离基座最近的 zone。

**结果**（200k）：
- success **20%** / lift **70%** / mean_reward **+22** ← 第一次正数

**诊断**（50ep）：
```
held 34%        ← 真抓
placed 0%       ← 但不放下
final_obj_z 0.061m  ← 物体被举着到 episode 结束
```

**新 hack**：reward 算账 `held_baseline 3.0 × 200 步 = +600` >> `placed_bonus 50` —— agent 选**抓着不放到超时**。

### v8 — 修"抱着 hack"，又走偏

**改动**：
- `W_HELD_BASELINE 3.0 → 0.0`（移除持续奖励）
- `R_PLACED_BONUS 50 → 200`（放大终止 bonus）

**v8 200k 结果**：success 0% / lift 0% (final)

**诊断**：lift 62% / held **0%** / OOB **58%**

**新 hack**：agent **撞飞物体触发 first_lift_bonus +20**（不抓，靠物体被弹起 z > 6cm 触发 lifted=True）：
```
v8 撞飞 obj:    +20 first_lift - 10 OOB = +10  ← agent 选这个
v8 真抓抱着:    0 (held_baseline 已为 0)
```

---

### v9 — 当前最佳：first_lift 要求 held=True

**改动**：
- `W_HELD_BASELINE 0 → 0.5`（小入场激励，但 250 步累积 = 125 < placed 200）
- `first_lift_bonus` 触发条件：`held=True`（不是只看 obj_z），堵撞飞 hack

**数学验证**：
```
v7 抱着到超时 vs 放下：    +600 vs +50    ❌ 抱着赢
v8 抱着到超时 vs 放下：    +0   vs +200   ✓ 放下赢，但 first_lift 撞飞 hack
v9 抱着到超时 vs 放下：    +125 vs +200   ✓ 放下赢
v9 撞飞:                    -10 (no first_lift, agent 不再选)
```

**v9 200k 结果**（yellow curriculum r=0.05）：
- success **20%** / lift 60% / mean_reward +1
- 50ep diagnose：placed **12%** / held 38% / final_obj_z **0.017m** ← 物体真落地了
- OOB 40%（副作用，动作太激进，待修）

**这是当前最佳**。

### 课程扩展失败：fine-tune 全部退步

试图 stage 2: load v9 + radius 0.05 → 0.10 训 200k：

| run | lift | reward |
|-----|------|--------|
| v9 stage 1 (从零 200k) | 38% | +22 |
| stage 2 (load v9 + 0.10) | 22% | -60 |
| stage 1.5 (load v9 + 同 radius) | 0% | -46 |
| stage 2 v2 (load v9 + 低 LR) | 10% | -47 |

**全都退步**。

**根因**：`SAC.load()` 默认**不加载 replay buffer**——fine-tune 重新从空 buffer 开始填，前期 critic 没"见过"成功 transitions，把已学策略洗坏。

**修复**：`train_sac.py` 训完自动 `save_replay_buffer`，`--load-from` 时自动从同目录加载 `replay_buffer.pkl`。

### v10 — 从零 600k：质变突破

放弃 fine-tune 路线，直接从零延长 v9 训练到 600k step。

**v10 600k 结果**（yellow curriculum r=0.05, ~10 min wall-clock）：

| 指标 | v9 200k | **v10 best 600k** | v10 final 600k |
|------|---|---|---|
| held | 38% | **66%** ↑↑ | 18% |
| placed | 12% | **46%** ↑↑↑ | 0% |
| lifted | 38% | 66% | 18% |
| oob | 40% | 30% ↓ | 12% |

**质变突破**：placed 12% → 46%，证实 reward 设计正确，只需更多训练。

**重要发现**：v10 final 比 best 严重退步（46% → 0%）—— SAC 后期 critic 漂移问题没根除。
- LR linear decay 缓解但没消除
- **结论**：以后总用 `best_model.zip`，不用 `final.zip`
- **future fix**：实现 EvalCallback 早停（连续 N 次 eval 不进步则终止）

### Stage 2 with buffer load — 课程化路线打通

**核心修复**：`SAC.load()` 现在自动加载同目录 `replay_buffer.pkl`（v10 训练时已存）。

**stage 2 v3 200k 结果**（load v10 best + buffer + radius=0.10）：

| 指标 | v10 stage 1 (r=0.05) | **stage 2 v3 (r=0.10)** |

| placed | 46% | **36%** |

### Stage 3 full table — 跨度过大，大幅退步

**stage 3 300k 结果**（load s2 + buffer + radius=None）：placed **6%**

| stage | radius | placed | 阶段 placed 损失 |
|-------|--------|--------|------------------|

### Stage 2.5 — 跨度过大，placed 跳水

**v10 stage 2.5 300k 结果**（load s2 + buffer + radius=0.20）：placed **2%** ↓↓↓

| stage | radius | placed | 阶段损失 |
|-------|--------|--------|----------|
| 1 | 0.05 | 46% | — |
| 2 | 0.10 | 36% | -10% |
| **2.5** | **0.20** | **2%** | **-34%** |

**根因诊断**：reward 缺"运送进展"信号。v10 配方下 phase B 只有势能项 `transport = -W_TRANSPORT × d_obj_tgt_xy`，定义"哪里好"但**不给"朝目标移动"的梯度信号**。
- stage 1/2：物体 5-10cm 内，agent hover 一下就 placed → 学得到
- stage 2.5+：物体 14cm+ 远，必须主动运送 → 学不到

### v11 — Progress Reward 尝试

**改动**：把 transport 从势能改成势能差（potential-based shaping）：
```python
W_PROGRESS = 10.0
progress = max(0, prev_d_obj_tgt - cur_d_obj_tgt)  # 朝 zone 靠近时给奖励
r += W_PROGRESS × progress × held    # 仅 held=True 时
```
为什么 `max(0, ...)`：
- 朝目标靠近 → 给奖励
- 远离 → **不罚**（避免 oscillate near zone 刷分 hack）

**v11 stage 1 结果**（200k from scratch, yellow r=0.05）：

| 指标 | v9 (no progress) | v10 (no progress) | **v11 (with progress)** |
|------|---|---|---|
| step | 200k | 600k | **200k** |
| held | 38% | 66% | **72%** ↑ |
| placed | 12% | 46% | **24%** ↑ (200k 翻倍 v9) |
| OOB | 40% | 30% | 34% |

**v11 stage 1 显著优于 v9 同期**，progress 让训练更高效。

**v11 stage 2 fine-tune 失败**（load v11 stage 1 + buffer + radius=0.10）：

| 指标 | v10 stage 2 (no progress, 200k) | **v11 stage 2 (with progress, 200k)** |
|------|---|---|
| held | 46% | **16%** ↓↓ |
| placed | **36%** | **8%** ↓↓ |

**根因**：v11 stage 1 ckpt 是 200k 中段，critic 还没充分整合 progress 估值。fine-tune 时 critic 重新调整 progress 预测，把短链抓取能力洗掉。

**修复尝试**：bug fix `target_override` 没 clip 到 RANDOM_X/Y 范围（stage 2.5 r=0.20 + cx=-0.15 ⇒ X 可达 +0.05 不可达区域）。bug 修复但 stage 2 退步未解决。

**结论**：progress reward 思路对，但需要 stage 1 训长（600k+）让 critic 充分；或者 W_PROGRESS 缩小（5 而不是 10）减少干扰。

## 整体经验总结

### Reward Gaming 攻防战 — 7 次 hack 反 hack

每次 reward 改动几乎都暴露一个新 hack。能进入下一阶段必须先堵上一阶段：

```
v1  touch + near_grip 重复 bonus 刷分          → 移除 dense bonus
v3  撞飞物体逃 step_penalty                    → OOB penalty -10
v4  Hover near object 拿满 reach 不抓          → first_lift bonus +20，GRIPPER_CLOSE -45°
v5  transport ×3 让 agent 急冲撞飞             → 回滚 W_TRANSPORT
v6  gripper 当推杆把物体滑到 zone              → placed 必须 ever_lifted
v7  抓起来不放手到超时拿 held_baseline 累积    → held_baseline 3 → 0.5, placed 50 → 200
v8  撞飞物体触发 first_lift +20（不抓）        → first_lift 必须 held=True
```

### 关键工程坑

| 坑 | 教训 |
|----|------|
| MuJoCo + multiprocessing fork 段错误 | macOS 必须用 `start_method="spawn"` |
| VecEnv callback freq 是 vec_steps 不是 env_steps | freq // n_envs |
| arm 撞地板下不去 | 三组 collision groups（floor/obj/arm 分组） |
| actuator kp 太软 | KP_BOOST=3 同时调 gainprm + biasprm |
| `target_entropy=auto` 在 6-dim action 太激进 | 固定 ent_coef=0.1 |
| 长训后期 critic 漂移 | LR linear decay 缓解 + 用 best_model 不用 final |
| `SAC.load()` 不加载 replay buffer | 显式 save/load_replay_buffer，否则 fine-tune 必崩 |
| `expert.py` 脚本式 placed 0% | 关节空间动作下 IK 没 orientation 约束，gripper 朝向不可控 |
| 课程化 zone_red 边缘比全场景还差 | zone 选中心 (zone_yellow) 而非边缘 |
| `randomize_objects` target_override 未 clip 到工作空间 | `np.clip(... RANDOM_X/Y_RANGE)` |

### 课程化经验法则

- **每 stage radius 不能 > 上一个的 2 倍**（0.05 → 0.10 OK, 0.10 → 0.20 边缘, 0.10 → full 必崩）
- **stage 1 必须 600k+ step**（短训 200k 学到的 policy + 200k 中段 buffer 不够稳定 fine-tune）
- **load_from 时必须加载 replay_buffer**，否则 critic 从空 buffer 重学，把已学策略洗掉
- **fine-tune 用更小 LR**（base / 3）

## 阶段 4：BC 路线（实施版）

启动 C 路线后实际遇到的所有坑和突破。

### 4.1 Expert 几何调试链（v1 → v9）

`expert.py` 在 05 env 下用 IK + scripted 5 阶段抓取-放置。从 placed 0% 调到 placed 20%（30 ep）经过 9 轮迭代：

| 版本 | 关键改动 | lifted | placed | OOB | 视觉问题 |
|------|---------|--------|--------|-----|---------|
| v1 | 基础 3-DOF IK + GRASP_Z=0.02 | 17% | 0% | 10% | gripper 穿地 4cm |
| v2 | GOTO_TOL 放宽 0.025 | 20% | 0% | 23% | 同 + close 挤飞 |
| v3 | GRIP_CLOSE_ACTION -0.4 | 30-57% | 0-3% | 40-50% | **lift 多为假阳性**（穿地挤飞瞬间 z>6cm） |
| v4 | GRASP_Z=0.06 不穿地 | 7% | 0% | 13% | 真实 lift 才 7%；finger 在 cube 上方夹空 |
| v5 | 6-DOF IK ROT=0.05 | 13% | 0% | 27% | 5 DOF 几何不能精确 6 自由度 |
| v6 | constrained pitch (joint2+3+4=0) | _IK 不收敛_ | _-_ | _-_ | sum=0 让 arm 必须伸直，z<0.05 不可达 |
| v7 | anti_underground IK 多重启选不穿地 | 33% | 7% | 0% | 好转，但 finger 单边评分（漏 FF.stl） |
| v8 | FF + GG 双 finger 评分 + GRASP_Z=0.075 | 73% | 0% | 0% | lift 翻倍但 cube 在 finger 中段被挤出 |
| v9 | closed-loop xy 修正 + GRIP_CLOSE -0.1 + friction 5.0 | **73%** | **20%** | 0% | ✓ 物理通了 |

### 4.2 关键几何与物理修正（v1 → v9 累计）

```
GRASP_Z_OFFSET:     0.02 → 0.075      finger 末端跨过 cube 高度而不穿地
GRIP_CLOSE_ACTION:  -0.4 → -0.1       松闭合 + 高摩擦"粘"住，避免几何挤压
geom_friction:      [2-3, .1, .01] → [5.0, 0.5, 0.1]  橡胶级摩擦
geom_solref:        [0.01, 0.5] → [0.04, 1.0]  软接触可压缩
geom_solimp:        [0.9 0.95 ...] → [0.6 0.8 ...]   松约束
IK 模式:            3-DOF EE pos → finger_target closed-loop （xy 精度）
finger 评分:        单 mesh → FF + GG 双 mesh z_min
```

### 4.3 关键发现：5 DOF SO-100 的固有限制

| 现象 | 原因 |
|------|------|
| IK 多解性极强 | 同一 EE 位置目标可对应多种姿态：朝下 / 朝侧 / 倒插穿地 |
| 加 6-DOF orientation 约束让 IK 失败 | 5 DOF 数学上控不了 6 约束，加 ROT_WEIGHT 必然牺牲 pos |
| `joint2+3+4=K` 强制 gripper 朝下 → IK 不可达低位 | 严格约束让 arm 必须伸直，3 DOF 不够 reach 地面物体 |
| **解法**：IK 多重启 + 后处理选不穿地的姿态 | 软约束方式，保留 pos 精度 |

#### BC Pretrain

`bc_pretrain.py` 用 demos 监督训 SAC actor（critic 不训）：
- 50 epoch × 256 batch
- **关键 bug fix**：MSE on tanh(mean) → MSE on unsquashed mean。expert action 大量 ±1 饱和，tanh 边界梯度趋 0 学不动；改在 atanh-空间训
- loss 5.77 → 4.00（unsquashed）

**BC alone eval 结果（30 ep, blue_cube full table）**：
- **lift_rate 80%** ← 项目最高
- placed_rate 0%
- mean_reward -22

BC 学到了"接近+抓+举起"，但**没学到"运送+放下"**——BC 是局部 imitation，没考虑 long-horizon。

#### SACfD（BC + demo replay buffer + SAC fine-tune）

| 配置 | lift | placed | mean_reward |
|------|------|--------|------|
| BC alone (起点) | **80%** | 0% | -22 |
| SACfD naive (lr=3e-4, 200k step) | **0%** | 0% | -95 |
| SACfD gentle (lr=3e-5, 50k step) | **0%** | 0% | -136 |

**两个 SAC fine-tune 都把 BC 完全洗掉**。LR 1/10 也救不回。

**根因**：BC 只训 actor，**critic 随机初始化**。SAC update 让 actor 跟随随机 critic 的预测——actor 几千步内偏离 BC 行为，无论 LR 多小。

**未实施**的修法（等需要时再上）：
- **Critic-only warmup**：用 demo offline 训 critic 数千步，等 critic 稳定再放 actor 跟随
- **AWAC / IQL**：BC + RL 的 SOTA 算法，actor loss 加 BC regularization
- 这些需要 1-2 小时实现 + 调试

## Reward Gaming 攻防战（教学复盘）

每次 reward 改动都暴露一个 hack。这是 manipulation RL 的常态：

| Bug | 修复 |
|-----|------|
| touch + near_grip 重复 bonus 刷分 | 移除中间 dense bonus（v1→v2） |
| OOB 自杀逃 step_penalty | OOB penalty -10（v3） |
| Hover near object 拿满 reach 不抓 | first_lift bonus +5→+20，GRIPPER_CLOSE 加深（v4） |
| transport ×3 让 agent 急冲撞飞 | 回滚 W_TRANSPORT 到 1.0（v6） |
| 用 gripper 推杆把物体滑到 zone | placed 加 ever_lifted 条件（v7） |
| 抓起来不放手到超时 | held_baseline 3→0.5，placed_bonus 50→200（v8/v9） |
| 撞飞物体触发 first_lift +20 | first_lift 要求 held=True（v9） |

**核心规律**：每次缩窄一处漏洞，agent 找下一个。设计 reward 时必须思考"这个 reward 有没有不通过任务也能拿到的方式"。

## 关键工程坑

| 坑 | 表象 | 修复 |
|----|------|------|
| MuJoCo + multiprocessing fork 段错误 | 8 envs 启动崩 | `SubprocVecEnv(start_method="spawn")` |
| VecEnv 下 callback freq 是 vec_steps | n_envs=8 时 eval_freq=10000 实际 80k env_steps 才 eval | `eval_freq // n_envs` |
| arm 撞地板下不去 | lift_rate 持续 0% | 三组 collision groups（floor/obj/arm） |
| actuator kp 太软（500） | ctrl 跟踪不到位 | KP_BOOST=3（动 gainprm + biasprm 同步） |
| `target_entropy = auto` 在 6-dim action 下太激进 | ent_coef 50k 降到 0.008，policy 过早 deterministic | 固定 `ent_coef = 0.1` |
| 500k 长训后期发散 | reward 200k 峰值后退步 | LR linear decay 到 base_lr × 0.1 |
| `SAC.load()` 不加载 replay buffer | fine-tune 退步 | 显式 `save/load_replay_buffer` |
| `expert.py` 脚本式抓取 placed 0% | BC 路线行不通 | 转反向课程（IK 在关节空间动作下 fragile，gripper 朝向不可控） |
